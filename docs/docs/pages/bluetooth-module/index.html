bluetooth

BLE 扫描、连接、服务发现和特征读写。

R7：新增 authorization_status() 以及 scan/connect/discover/read/write 的 *_async(..., budget=...) 入口。扫描会发布 partial result，取消会停止底层扫描；controller 按 MiniApp owner 隔离，另一个活跃 owner 不能抢占连接。异步入口不会把原生服务不可用伪装成空扫描/空服务或普通连接错误：终态为 failed，result.error.code == "bridge_unavailable"。历史同步入口的空值兼容行为保持不变。

异步名称：scan_async()、connect_async()、discover_services_async()、read_async()、write_async()。

BLE 中心模式：扫描外设、连接、发现服务、读写特征值，以及订阅 Notify/Indicate 更新。

边界：面向低功耗蓝牙中心端（扫描/连接其他设备），不是普通 HTTP/WebSocket 网络。若要让本机被扫描，请用 ble_peripheral。需要蓝牙硬件与系统授权；扫描、连接放在按钮回调，不要在 body() 里自动执行。

#连接与发现

connect(uuid) — 成功返回 "ok"，失败返回错误描述字符串（不是异常）。

discover_services(uuid) — 返回服务字典列表（含特征 UUID），须先连接成功。

扫描、连接和服务发现各自只允许一个原生请求在执行；连接忙时返回 operation_in_progress，历史扫描/服务发现的数组 ABI 保留 [] 兼容回退。回调核对运行 owner 与精确的原生外设对象，其他外设及迟到回调不能完成当前请求。取消 connect_async() 或 discover_services_async() 会主动断开该运行 owner 的目标外设连接，包括尚未连接完成的请求；同外设上的订阅也会终止，其他外设不受影响。发现超时/失败会使该连接退役，重新连接后再试。取消待连接请求的实际终态可能通过 didFailToConnect 返回，仍会正确释放退役标记。

#读写特征

write() 的第四个参数必须是 Base64 字符串，不要直接传 bytes。

#写入模式与单包长度

服务发现中的 write 表示支持带确认写入；write_no_resp 表示支持无响应写入，不是错误名称。 根据设备协议显式选择模式：

  • response=True（默认）：要求特征具有 write。返回 True 表示 CoreBluetooth 收到设备的成功写入确认；不表示设备已完成业务指令。
  • response=False：要求特征具有 write_no_resp。返回 True 只表示已按流控提交给 CoreBluetooth，没有设备确认，也不保证设备已经收到或执行。需要业务确认时，按设备协议使用 Notify/Indicate 或其他响应特征。
  • 不会在模式不支持时静默切换。旧四参数调用继续使用带确认写入；仅支持 write_no_resp 的特征必须指定 response=False。

maximum_write_length(peripheral_uuid, service_uuid, characteristic_uuid, *, response=True) 返回实际连接当前允许的单包长度，两种模式可能不同；重连后重新查询。数据超过该限制会抛出 payload_too_large，error.details["maximum_write_length"] 提供可用长度。不会自动拆包或补换行， 因为包边界、分片标记及重组属于设备协议；不要固定假设每包都是 20 字节。

write_async(..., response=False, budget=...) 使用相同模式与布尔结果，推荐在界面回调中使用。 异步取消定位到该请求：未发送的请求从队列移除，不会主动断开其他外设；已经提交的数据无法撤回。 带确认写入提交后取消或超时会使该连接退役，防止迟到确认完成后续请求，同连接的订阅与待发送写入也会结束。 同步调用与旧 C ABI 复用同一队列。旧运行桥仅保留默认带确认同步写入兼容，新模式与长度查询缺少对应桥时明确报错。

#连续发送与失败处理

同一外设的写入按原生入队顺序串行发送；不同外设各自推进。系统发送缓冲满时等待 peripheralIsReady(toSendWriteWithoutResponse:) 后继续，不通过固定 sleep 猜测发送速度。 并发启动的异步调用不承诺 Python 调用顺序；设备协议要求命令顺序时，等待前一个 handle 的结果后再发下一条。

每个 Python 运行最多保留 32 个待完成写入、256 KiB 原始负载；队列满抛出可恢复的 write_queue_full，不丢弃已有命令。单个请求从入队开始最多等待 10 秒；异步默认预算为 12 秒、 最多并发 4 项，调用方只能收紧。字节预算同时约束原始负载和布尔结果（至少 4 字节），过小会在提交前失败。 运行结束、蓝牙关闭或外设断开会结束未完成写入，不会自动重连或重发。

写入失败抛出 AppUIError。如果 error.details.get("submitted") 为 True，说明数据已经提交过， 设备是否执行可能未知；先根据设备协议核对，不能因为超时直接重复发送控制命令。 write_not_supported / unacknowledged_write 检查模式； not_connected / disconnected 检查连接；payload_too_large 检查长度与设备分片协议。

#原生实现与验证边界（BLE-WRITE-20261102）

正式 Python owner 仍是 BluetoothBridgeManager 与 pyboot.bluetooth。 使用 Apple 公共 CBPeripheral.writeValue(_:for:type:)、maximumWriteValueLength(for:)、 canSendWriteWithoutResponse 和可发送 delegate 回调；原生能力满足需求，无新增 BLE 库或系统权限。 现有 BluetoothWriteQueue 提供有界 FIFO/字节记账，CoreBluetooth 对象和运行 lease 仍由原 manager 持有。 回调核对外设对象、特征对象、运行归属及已提交状态。未确认的带响应写入会隔离连接，旧四参数 C 符号保留， 新增 JSON C 符号由既有 symbol keeper/export owners 保留。

Agent 的 native_hardware.bluetooth_write 保留既有异步 MainActor 权限与会话适配， 复用同一 FIFO/容量策略和原有有界异步等待；with_response=false 的回执为 submitted=true, acknowledged=false，不自动读回或伪造设备确认。省略参数保留原有优先带确认的自动选择， 显式指定模式时必须得到支持。没有 App 页面、Toast、通知、权限或数据格式迁移； Python/Agent 错误继续沿已有结构化错误合同（UI-32 兼容边界）返回。

#Notify / Indicate 订阅

先扫描、连接、发现服务，再对包含 notify 或 indicate 属性的特征订阅。subscribe() 仅在 CoreBluetooth 的通知状态回调确认成功后返回；不会把已提交请求当作订阅成功。若特征同时支持两种模式，Apple 的 setNotifyValue 使用 Notify；仅支持 Indicate 的特征使用 Indicate，不提供强制覆盖系统选择的参数。

批次包含 subscription_id、state、events、pending_events、pending_bytes、dropped_events 和 dropped_bytes；异常终止另含 error.code/message。事件含单调递增 sequence 和 Base64 data。丢弃计数是从创建起累计值，不会因 poll() 清零；序列跳号也能表示未保留的更新。

每订阅默认最多保留 128 个更新、256 KiB 原始负载，调用方只能收紧。队列满时丢弃最早更新；单个负载超过字节预算时丢弃该更新，均增加显式计数。poll(max_events=...) 每次最多取 128 个更新，不等待新数据。一个运行 owner 最多有 16 个活动订阅；最多保留 64 个活动/终态 token，较旧终态 token 可能返回 subscription_expired。

运行结束、权限 lease 失效会清理原生订阅与连接；token 不可跨运行或 owner 复用。主动断开在等待回调时为 disconnecting，实际断线回调后为 disconnected；蓝牙不可用返回 unavailable。退订确认后为 closed；已排队的数据仍可在 token 保留期间取出。状态变化或数据回调失败返回 failed。没有后台持续运行承诺，也不会自动重连或重新订阅。

CoreBluetooth 的主动读取和通知共用值回调，因此在同一次连接中，订阅过的同一特征改用主动读取会抛出 notifications_conflict；需要先退订、断开重连并重新发现服务，隔离迟到的通知。其他特征仍可读取。仍在读取或有未决读取回调时订阅会失败。每 owner 最多记录 256 个不同特征的回调屏障，达到时先断开相关连接再继续。订阅/退订最多等待 10 秒；超时或无法确认状态时使该连接退役并断开，避免迟到回调混入下一次操作，其他同连接订阅也会结束。等待 didDisconnect 后才允许重新连接。

此接口使用既有蓝牙授权、运行归属与原生资源清理，不在 CoreBluetooth 回调线程执行 Python 函数。subscribe/close 是同步、有界等待接口；AppUI 的主交互回调应通过现有后台任务方式调用，UI 定时器中仅做非阻塞 poll()。真机 Notify-only、Indicate-only、断线、关蓝牙与高频数据验收须单独执行；主机替身或模拟器不能代替真实外设验证。

原生选型依据：2026-11-01 核对当前 iPhoneOS SDK 27.1 的公开 CBPeripheral.h，复用 setNotifyValue(_:for:))、通知状态回调) 与既有 CoreBluetooth manager。Apple 已满足订阅需求，无新增第三方 BLE 栈、系统权限或持久数据；订阅句柄与轮询使用原生服务提供的有界事件缓冲。系统 SDK、运行归属或真实外设回调证据变化时复核。源码/主机模型检查与真实 iOS 外设验收分别记录。

#推荐流程

  1. state() 确认 powered_on
  2. scan() 找到目标 uuid
  3. connect(uuid)
  4. discover_services(uuid) 获取 service_uuid / characteristic_uuid
  5. read() / write()
  6. disconnect(uuid)（建议 try/finally）
