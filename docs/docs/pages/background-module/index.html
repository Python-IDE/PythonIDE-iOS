iOS 原生模块 / 连接与后台

background

后台任务、保活与 BGTask 调度。

为当前 MiniApp owner 提供短时、可中断的 UIKit 后台任务保护和应用状态查询。

真实性边界：PythonIDE 目前不能在进程被系统唤醒后恢复任意 MiniApp Python 回调。因此 supports_durable_scheduling() 固定为 False；兼容的 schedule_refresh() / schedule_processing() 明确返回 False，checked 版本抛出 durable_python_scheduling_unsupported。它们不再提交一个与 MiniApp 无关的宿主任务并制造“成功”。

#正确用法

begin_task() 只表示 UIKit 接受了有限后台时间申请；持续时长由 iOS 决定，随时可能到期，不保证工作完成。remaining_time() 只是瞬时估计。

#API

API真实行为
begin_task() / end_task()owner-scoped、成对使用的有限 UIKit background task。
remaining_time()系统估计的剩余秒数。
app_state()active / inactive / background。
status()返回 owner、任务状态、finite_task_last_end_reason / finite_task_last_ended_at 和 durable_python_scheduling_supported=False。
supports_durable_scheduling()当前固定为 False。
schedule_refresh/processing()兼容入口，明确返回 False。
schedule_*_checked()明确抛出 unsupported 错误。
begin_task_async/end_task_async()有超时、并发预算的 OperationHandle。
start_keep_alive()/stop_keep_alive()音频业务兼容接口，不是通用保活能力。

不要用静音音频、无限循环或阻塞 sleep 绕过平台后台政策。大文件网络传输使用 background_download，用户提醒使用 notification。

expiration 回调会把 finite_task_last_end_reason 置为 "expired"；显式结束、回到前台、owner teardown 分别可见为 ended、foregrounded、session_cancelled。真机验收仍应覆盖锁屏/切后台、expiration、owner teardown 与成对释放；模拟器无法证明系统调度行为。

公开异常类型为 BackgroundError；严格入口是 schedule_refresh_checked() 与 schedule_processing_checked()。
