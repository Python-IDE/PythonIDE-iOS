appui / 示例

相册浏览器

LazyVGrid、AsyncImage、PhotoPicker、详情导航和全屏预览。

本页演示 LazyVGrid、AsyncImage、PhotoPicker、NavigationStack 和懒加载 sheet。示例同时处理远程 URL 与选择器返回的本地文件，但不会手工拼接 file://。

真实边界：PhotoPicker 返回的是当前运行可读的文件路径，不是永久 Photos 资产 ID。FileResource / MediaSource 的授权 lease 只属于当前 MiniApp session；不要把这些路径持久化后跨运行复用。

#预期效果

运行后会出现图片网格。用户可以从系统照片选择器添加图片、进入详情、打开预览、关闭预览以及显式重试失败的加载。

#状态设计

示例把每项拆成稳定业务身份、来源种类和来源值：

字段作用
items[].idForEach / 导航 / 图片缓存使用的稳定身份。
items[].kindremote 或 file。
items[].valueHTTPS URL 或选择器返回的本地路径。
items[].version内容版本；同一业务图片内容变化时递增。
reload_nonce用户主动重试的瞬时标识，不参与持久缓存身份。

本页使用 persist=False，避免把运行期文件路径写入持久 State。

#为什么这样写

  • 本地图片通过 MediaSource.file(FileResource(path, access="read")) 表达；字符串 url= 仍兼容，但新代码不应靠拼接 file:// 猜测授权。
  • cache_key 表示稳定业务资源，cache_version 表示内容版本。不要每次渲染生成 UUID，否则缓存项只增不复用。
  • reload_token 变化会触发一次重新请求，但不会创造新的持久缓存身份。
  • content=sheet_root 传入 callable。关闭时 builder 保持休眠；打开期间 generation 稳定，但其他状态变化仍可能让当前内容重新构建。
  • 动态项显式 .id(item["id"])，插入、删除和重排时不会把行内状态错误地交给另一张图片。

#权限、缓存与惰性边界

  • 系统照片选择器通常不需要授予整个照片库读取权限；它只把用户明确选择的项目交付给当前运行。取消可能返回空列表。
  • 远程图片仍需 MiniApp 的 network 权限和匹配的 allowedNetworkHosts。
  • LazyVGrid 让原生视图系统延迟创建屏幕外单元格，但 Python 的列表推导和 AppUI tree 仍会生成所有声明项；因此仍需限制数据量并使用分页。
  • AsyncImage 的磁盘缓存有 TTL、条目/总大小预算和 LRU 清理。命中是否复用由 source、owner、cache_key、cache_version 与 policy 共同决定；签名 URL 不会自动推断业务版本。
  • on_dismiss 在原生或程序化关闭后用于清理。不要依赖它替代 Binding 的真假状态回写。

#常见错误

错误问题修正
"file://" + path可能错误转义，也绕不开 lease 校验使用 FileResource + MediaSource.file
把 picker 路径持久化到下次运行原 session lease 已失效当前运行消费；需要永久资产能力时使用 photos 模块
每次 body 都设置随机 cache key缓存无限分叉、无法复用稳定 cache_key + 有意义的 cache_version
content=sheet_root()关闭时也会提前构建内容传 content=sheet_root
依赖 LazyVGrid 避免 Python 构建Python tree 仍包含全部项分页、限制数量、稳定 key
