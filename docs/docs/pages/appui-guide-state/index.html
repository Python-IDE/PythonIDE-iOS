appui / 指南

状态管理

State、ReactiveState、Timer 和批量更新的使用边界。

appui 的界面由状态驱动：状态变了，body() 重新执行，View 树重新生成。状态代码要短、集中、可预测。

#预期效果

示例会展示表单字段、列表选择、搜索结果、滑块和计时器如何由状态驱动刷新。

#选择哪种状态

用法选择说明
表单字段、开关、当前 tab、普通计数State最常用，写入后触发重建。
有版本、需要迁移的普通持久数据PersistentState用稳定 key、业务 schema 与显式迁移函数。
token、密码等单个敏感值SecureState同步写入按 MiniApp 隔离的设备 Keychain。
高频数值或大数组ReactiveState可走实时快路径，减少整树重建压力。
不想触发重建的对象Ref保存句柄、缓存对象、一次性资源。
列表 / 字典增删改ObservableList / ObservableDictState 会自动包装 list/dict，让局部变更也能通知界面。
派生值computed从状态计算，不手动同步副本。
状态变化后的副作用effect用于日志、保存、触发外部动作。

普通页面先用 State。只有高频更新或大数据刷新已经明显卡顿时，再考虑 ReactiveState。SecureField 只负责遮挡文字；是否安全持久化由 SecureState / keychain 决定。

MiniApp 中 State 默认持久化 JSON 兼容字段。密码、token 等明文必须用 transient=[...] 排除（或存入 Ref），需要长期保存时使用 keychain；SecureField 只遮挡界面显示，不会自动关闭持久化。

#State

State 适合绝大多数页面状态。控件读取当前字段，on_change 或按钮回调写回字段。

多个字段一起更新时，用 batch_update：

to_dict() 返回递归分离的深快照。继续修改 snapshot 里的嵌套 list / dict 不会反向修改 State；它适合日志、序列化和把当前状态交给其他任务。

#ObservableList / ObservableDict

列表和字典放进 State 后会被包装成可观察容器。append、pop、update、list 的 *=，以及 dict 的 |= / popitem() 等局部变更都会递归包装新值，并在实际变化后通知一次界面。

如果只是偶尔改列表，也可以重新赋值：state.items = list(state.items) + ["New"]。

#Ref

Ref 保存“不属于界面事实源”的对象，写入不会触发重建。

典型用途是保存 timer、网络任务、播放器句柄、滚动代理等。不要把需要显示到界面的值放进 Ref。

#computed 与 effect

computed 用来声明派生值，避免维护两份状态。

depends_on 中的每个名字都必须是当前状态已有的字段，写错会在声明时直接报错，避免派生值悄悄不刷新。相同声明在 body() 重建时会复用，不会不断追加注册；声明从新一代 View 树中消失时会自动退出。

effect 可以返回一个 cleanup 函数。依赖变化后再次运行、声明退出或当前 run 会话结束前，旧 cleanup 都只执行一次：

副作用不要直接写进 body()；body() 应该只负责声明并返回 View。

#Binding、校验与 ReactiveState

支持双向状态的控件可以直接接收 Binding。最短写法是 state.bind.<field>：

旧写法 appui.Slider(**appui.bind(state, "progress"), ...) 继续兼容。除了常用输入控件，sheet、焦点、滚动位置、列表 / tab 选择、TextEditor 辅助状态、地图、图表和 Web 导航状态等公开的受控参数也可以直接传 Binding。

需要在“界面值”和“存储值”之间转换时，用 ValueCodec。解码、校验或回编码失败都会拒绝本次输入，状态不会被改写：

控件输入会携带字段 revision。Python 返回 accepted、canonicalized、rejected、stale 或 error 回执；原生界面只采用匹配当前会话、View 树、Binding 和 mutation 的回执。被拒绝或过期的乐观输入会回滚到 canonical_value，额外的 on_change 只在写入被接受后收到通知。通常不需要手工处理回执；测试自定义 codec 时可调用 binding.propose(...) 查看 BindingResult。

ReactiveState 适合频繁更新的属性，例如 slider 值、拖动坐标、图表数据。它可以绑定实时属性通道，减少高频整树重建。

普通表单不需要上 ReactiveState；只有高频更新或大数据刷新明显卡顿时再用。底层 bind_handles() 可以让同一字段绑定多个原生实时 consumer；重复登记会向所有当前 handle 扇出，传 0 会清空该字段的 handle。handle 会绑定当前 session / generation，热重载或新一代运行时会丢弃旧 handle；普通业务控件仍应优先使用 Binding，不需要手工管理它。

需要显式声明原生二进制 property 时，使用 BinaryField；旧的 (initial_value, prop_id) 仍兼容。业务数据本身如果是长度为 2 且第二项为整数的 tuple，用 StateValue 明确走 JSON 路径：

BinaryField 只接受 bool/int/finite float/string 与 1...65535 的 property id；无效声明在启动前失败，不会等到原生 push 时静默降级。

文本输入期间，运行时会区分焦点、输入法组合态和外部状态更新。组合中的草稿不会被旧 render 覆盖；被延后的规范值会在组合结束后按 revision 收敛。TextEditor.selection 的 start / length 使用 UTF-16 code unit，与 Apple 的 NSRange 一致；包含 emoji 时不要当作 Python 字符下标。新代码可用 TextSelection(start, end) 明确表达半开区间，旧的 (start, length) 和 mapping 写法保持兼容：

#持久化身份与清理

需要跨运行稳定恢复时，优先显式指定 persist_key。没有显式 key 时，运行时会按声明位置分配稳定身份；同一工厂连续创建多个 State 会获得不同实例槽，避免互相覆盖，同时第一个实例继续兼容旧 key。

底层快照 envelope 只接受当前支持的 schema。schema_version 是独立的业务数据版本：已存版本不同（包括旧记录没有版本）时，运行时调用 migrate(values, from_version, to_version)；迁移必须返回 JSON-compatible mapping。迁移抛错或返回错误类型时，声明默认值保持不变，旧记录也不会被部分覆盖；成功结果会按目标版本重写。

#SecureState

固定业务 key 的单个敏感值可以直接使用 SecureState。它继承 State 的 value 和 bind.value 用法，但每次接受的写入都会同步保存到现有 Keychain，而不会进入普通 State / UserDefaults 快照：

Keychain 项沿用宿主的 MiniApp owner namespace、storage capability 和仅本机解锁可访问策略。SecureState 适合固定 key；服务名 / 账号由用户动态选择、需要“点保存”才落盘或读取前要求生物识别的凭据库，继续直接使用 keychain。从 Keychain 读出的明文仍会存在当前进程内存中，不要写日志，也不要复制进普通持久化 State。

#Timer 与自动刷新

Timer 要在模块级创建，初始化时传入 action。不要在 body() 里创建 Timer。

Timer 与 auto_refresh 都由当前 AppUI session / generation 持有；停止、替换运行或热重载淘汰旧一代时会取消旧资源并拒绝迟到回调。auto_refresh 适合临时脚本和 demo。正式页面优先用明确的状态写入、绑定和生命周期。

#Checklist

  • 需要显示到界面的值放在 State / ReactiveState。
  • 列表和字典可以依赖 ObservableList / ObservableDict，也可以重新赋值。
  • body() 里不要创建 timer、请求、文件写入。
  • 多字段更新用 batch_update。
  • 自定义双向转换使用 ValueCodec，不要让 on_change 各自实现不同的校验规则。
  • 持久化业务状态优先给出稳定 persist_key；清空使用 clear_persisted()。
  • 持久结构升级时同时给出 schema_version 与纯迁移函数；敏感单值用 SecureState。
  • 高频数据先确认瓶颈，再换 ReactiveState。
  • 行级操作使用稳定 id，不使用过滤后的下标。
