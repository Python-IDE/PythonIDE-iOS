iOS 原生模块 / 连接与后台

weather

当前天气与每日/每小时预报（WeatherKit）。

通过 Apple WeatherKit 按坐标读取当前天气、每日预报与小时预报。

发布阻断项：当前公开 weather API 只返回天气数据，没有返回 WeatherKit 要求展示的 Apple Weather 标识、attribution 与法律链接。因此它目前只能用于开发验证，不能据此直接发布面向用户的天气界面。等公开 attribution API 补齐后，才应把 WeatherKit 数据展示给用户。

#当前真实能力

项当前行为
current(lat, lon)同步等待原生 WeatherKit 请求并返回字典。
daily(lat, lon, days)同步等待并返回每日列表。
hourly(lat, lon, hours)同步等待并返回小时列表。
current_location()需要当前 MiniApp 的 location authority 和系统定位授权，再使用设备坐标查询。
取消/超时没有公开 OperationHandle；原生最多等待约 30 秒，Python 无法取消已发起请求。
attribution当前未公开，用户可见展示不满足发布要求。

还需要宿主签名包含 WeatherKit entitlement，并且网络可用。调用应放在用户动作或受控任务中，绝不能写进 AppUI body()。

#API 参考

API返回重要边界
current(latitude, longitude)dict同步、不可取消；调用前自行校验坐标。
current_location()dict需要 location authority/权限；使用的缓存坐标没有公开 age/accuracy 保证。
daily(latitude, longitude, days=7)list[dict]调用前自行限制 days。
hourly(latitude, longitude, hours=24)list[dict]调用前自行限制 hours。
WeatherError异常code 来自原生响应；不要假设每个系统错误都有稳定细分类。

常见当前天气字段：temperature、feels_like、condition、symbol、humidity、wind_speed、uv_index、is_daylight。温度为摄氏度，风速为 m/s，湿度和降水概率通常为 0...1。

每日项通常包含 date、condition、symbol、high、low、precipitation_chance；小时项通常包含 date、condition、symbol、temperature、precipitation_chance。

#定位调用

系统定位授权不等于可以跨 MiniApp 使用位置：当前运行还必须拥有 location capability。返回坐标可能来自系统缓存；本模块没有公开精度和时间戳筛选参数。

#失败路径

情况当前表现
bridge / WeatherKit 不可用抛出 WeatherError，常见 code 为 unavailable。
entitlement 或 WeatherKit 授权问题抛出 WeatherError；具体 code 取决于原生映射。
定位未授权current_location() 失败。
请求超过同步等待窗口返回超时错误，但后台 Task 可能尚未被取消。
连续快速调用每次都会创建独立请求，没有 owner-scoped 去重/取消。

#不要这样做

  • 不要发布没有 Apple Weather attribution 的用户可见天气卡片。
  • 不要在 body()、滚动回调或高频 timer 中调用。
  • 不要把 WeatherError.code 当成穷举稳定枚举。
  • 不要假设 current_location() 返回的是刚刚采集的高精度位置。
  • 不要并发批量发起大量同步请求。
